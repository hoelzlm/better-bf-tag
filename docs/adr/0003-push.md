# ADR 0003 – Push über FCM (Android) und APNs direkt (iOS)

- **Status:** Vorgeschlagen
- **Datum:** 2026-10-07

## Kontext

Alarme müssen die Handys auch erreichen, wenn die App geschlossen ist. Es soll ein eigenes
Backend geben, Google- und Apple-Dienste sollen so wenig wie möglich genutzt werden.

## Optionen

1. **FCM für Android + iOS:** ein API für beide Plattformen, aber iOS-Pushes laufen zusätzlich
   über Google, und die App braucht das Firebase-iOS-SDK.
2. **FCM für Android, APNs direkt für iOS:** jede Plattform über ihren nativen Weg, auf iOS kein
   Firebase.
3. **UnifiedPush / ntfy (selbst gehostet) für Android:** ohne Google, aber Nutzer müssen eine
   Distributor-App installieren, und das Verhalten im Doze-Modus ist unsicher. Für Jugendliche
   nicht zumutbar.

## Entscheidung

**Option 2.** Das Backend spricht direkt mit FCM HTTP v1 und mit APNs.

## Konsequenzen

- Zwei Push-Implementierungen im Backend (beide klein, < 150 Zeilen).
- Das Firebase-Projekt wird nur für Cloud Messaging genutzt (kein Analytics, kein Crashlytics).
- Die App braucht auf iOS ein eigenes Token-Handling (native APNs-Registrierung).
- Fallback: Wird das zu aufwendig, kann iOS jederzeit auf Option 1 wechseln (`firebase_messaging`
  ist dann ohnehin schon in der App).
